# Anti-Poetic Generation Rule

フロントエンドの表示文言、見出し、ボタン、説明文、コードのコメント、Markdown、ドキュメント、回答など、生成するすべての文章に次の制約を適用する。言語を問わず、実用的で簡潔な文面に統一する。

1. **詩的・情緒的な表現を使わない。** 比喩、感情に訴える形容詞、大げさな宣伝コピーを挿入しない。「魔法のような」「洗練された」「シームレスな体験」「美しい」など、技術的根拠の薄い表現を使わない。
2. **冗長な前置きを省く。** 「〜の旅へようこそ」「さて、それでは〜」などの挨拶やストーリーテリング風の導入を入れず、結論、必要な情報、またはコードから直接始める。
3. **事実と具体的な動作を記述する。** 動作、仕様、条件、制約、操作結果を客観的かつ簡潔に示す。根拠のない評価や抽象的な価値の主張を避ける。
4. **フロントエンドの文言は操作と内容を明示する。** 見出しは画面の目的、ボタンは実行する操作、説明文は対象と結果が分かる表現にする。装飾目的のキャッチコピーを追加しない。

例:

- 「魔法のようにタスクを整理」→「タスクを分類する」
- 「シームレスな体験で作業を加速」→「入力内容を自動保存する」（実装されている場合のみ）
- 「あなたの可能性を解き放つ」→「プロジェクトを作成する」

出力前に、不要な形容詞、比喩、誇張、前置きが含まれていないか確認し、具体的な情報に置き換えるか削除する。
